# 시설 레이블 표시·인식 수정 (로컬 검수)

기준 작업본: `outputs/project-foundation-20261115/github-ready`. 원격 main 시작점은 `4418af5539a3c363bfad2c9ffe7f918842b9b144`. 로컬 정리 커밋은 `bf2082126ba85c9e59778da9bee03e7afff1eadf`이며 Git 이력은 서로 다르다. 이번 수정 전 대상 런타임 파일의 내용은 원격과 동일함을 확인했다.

## 범위와 원인

- 종합운동장·야구장: 기존 이름과 ID를 유지하고 지도 글자를 표시했다. 비선택 바닥면 때문에 빠지던 3D 레이블 인식을 실제 표면 위에서 복구했다.
- 본부 테니스장·공대 테니스장: 동일 방식. 면수는 붙이지 않았다.
- 자하연: 기존 `jahayon` ID, `nav.facilities.outer` 수면 전체를 지도·3D 인식에 사용한다. 수면 높이·보행 제외영역·충돌은 변경하지 않았다.
- 공대폭포: 기존 `nav.waterfall73`/`waterfall73` 시설의 외곽·폭포 표면에 표시용 이름 `공대폭포`를 연결했다. 이전 이름 레코드가 없으므로 이 명시적 승인에 한해 표시용 레코드 하나를 사용한다. 새 모델·검색 목적지·도착 앵커는 만들지 않았다.
- 아크로폴리스: `place-acro`를 유지. 기존 작은 사각형 대신 library17의 `main-front-*` 메인 계단 6구간과 그 출처를 가진 계단참 4곳을 재사용한다. 건물이나 계단 사이 녹지까지 덮는 큰 사각형은 사용하지 않는다.

공통으로 미니맵·전체 지도 글자/hover와 3D 인식이 같은 시설 경계를 사용한다. 지도에서는 건물을 먼저 검사하고, 3D에서는 실제 교차 거리로 가까운 건물이 뒤쪽 시설을 가리도록 한다. 숨겨진 판이나 충돌체를 추가하지 않고, 기존 메시의 isPickable/checkCollisions 속성도 바꾸지 않는다. 다른 이름 레지스트리와 구역 경계 데이터는 그대로 유지했다.

## 검증

`node scripts/verify-facility-labels.cjs`

실제 앱의 초기 데이터 준비 코드를 실행한 뒤 대상 7개(테니스장 2개 포함)의 경계·ID·중복을 검사했다. Node DOM/Canvas 환경에서 1000×700, 375×700 및 미니맵의 대상 글자 표시/hover, 메인 계단과 참 10곳, 건물 우선 인식, 드래그/클릭 구분을 확인했다. Babylon NullEngine의 실제 광선 교차로 비선택 수면, 메인 계단 표면, 앞쪽 건물 가림과 충돌 속성 보존을 검사했다.

이는 실제 브라우저 화면·마우스 실기 검사가 아니다. 현재 브라우저 제어 도구가 없어 화면 캡처와 실제 브라우저 확인은 하지 못했다. 반복 지상 이동·캠퍼스 전역 검사는 하지 않았다.

## 로컬 확인

저장소 루트에서:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

`http://127.0.0.1:8765`를 열고 전체 지도 및 미니맵에서 해당 시설 위로 마우스를 이동한다. 작은 화면은 보이는 범위와 겹침을 고려해 글자를 배치하고, hover로 이름을 확인할 수 있다. 3D에서 자하연 물 위와 중앙 메인 계단 각 구간도 확인한다. 별도 번들 빌드가 필요 없다.

이번에는 Sites 버전 저장·배포·공개 권한 변경을 하지 않는다. 원래 `campus-walk` 작업본은 변경하지 않는다. GitHub와 로컬 작업본은 자동 동기화되지 않으며 바탕화면의 별도 클론에서는 원격 변경을 pull해야 한다.
