# BUILD112 로컬 보안·보관·게시판

공개 배포하지 않았다. 기존 8766 실행 서비스와 실제 DB·자격은 읽거나 재시작하지 않았다. 검증은 임시 자격·DB·포트만 사용했다. README, 저장소 공개 범위와 호스팅 계약은 별도 작업이다.

## 이번 서버 변경

- 정적 파일은 허용 확장자와 실제 경로(realpath)를 검사한다. 숨김 파일·상위 경로·정적 루트 밖 심볼릭 링크는 거절한다. 이 검사는 서버 파일시스템 자체를 공격자가 수정할 수 있다는 가정까지 방어하지 않는다.
- JSON 본문은 객체만 허용한다. 토큰 비교는 UTF-8 바이트 길이로 확인해 잘못된 토큰도 500 오류 없이 거절한다.
- 비밀번호 파생은 scrypt, 동시에 최대 2건, 네트워크당 로그인 10회/15분. 관리자 세션은 최대 32개·8시간·메모리 보관. 실제 비밀번호와 원본 사용자 DB는 검사하지 않았다.
- 관리자 문서는 같은 출처 스크립트만 허용하는 CSP, frame-ancestors none, X-Frame-Options DENY를 적용한다. 글·공지·피드백은 textContent로 출력하고 HTML로 해석하지 않는다.
- HTTP 요청·헤더 대기 10초, keep-alive 5초, 헤더 64개, 소켓당 1000개 요청. 업그레이드는 네트워크당 600회/분, 제한 테이블 최대 4096개. WS 2KB/40메시지/초, 대기 소켓 제한과 재접속 세션 상한을 유지한다.
- ws 8.23.0의 자동 Pong 대기 기본 상한 60을 변경하지 않았다. 현재 npm audit에서 알려진 취약점 0건을 확인했다. 이는 번들된 모든 브라우저 라이브러리·서버 운영체제·미발견 취약점의 안전 보장이 아니다.
- 동일 Origin/Host, CSRF, JSON Content-Type, production Secure/HttpOnly/SameSite=Strict 쿠키, 명시 IP 프록시 신뢰는 기존 검사와 함께 유지했다. IP 제한만으로 분산 공격이나 공용 NAT의 오탐을 모두 해결하지 않는다.

## 공용 공간 기본값

사용자 확정 사항은 모두 같은 캠퍼스에 접속하고 가까운 사람만 표시하는 방식이다. BUILD110의 3개 채널 기본값을 BUILD112에서 **하나의 공용 공간·현재 접속 상한 300명**으로 정정했다. 02/03의 이전 브라우저 설정은 01로 이전한다. 128단위 공간 격자, 180 진입/220 이탈, 가까운 최대 24명, 200ms 관심 대상/100ms 상태 전송은 그대로다. 숫자는 장면 단위다. 300명 초과를 무제한 수용하지 않으며, 만원 상태와 재시도 UI가 있다. 일반적인 다중 채널 함수는 내부 호환/검사용으로 남지만 기본 제품에서는 채널 선택을 노출하지 않는다. 기존 실행 중인 BUILD111은 재시작하지 않았으므로 이 변경은 새 BUILD112 인스턴스에서만 적용된다.

## 공지와 비공개 피드백

공지: 관리자 작성/수정/삭제, 임시 저장 또는 공개. 시작 화면은 공개 공지만 읽는다. 피드백: 1~1000자, 브라우저 소유자당 1분 1회·24시간 3회, 네트워크당 120회/시간, 같은 내용 24시간 중복 방지. 요청 키로 재전송 중복을 막는다. 관리자만 본문 목록을 읽고 처리/재개/삭제할 수 있다. 공개 피드백 목록·메일 전송·외부 업로드·답변 기능은 없다. 관리자 삭제는 본문을 비우고 삭제 상태만 남긴다. 개인정보를 쓰지 말라는 안내와 실패 시 초안 보존을 적용했다.

DB 스키마는 1→2로 추가 테이블만 생성한다. 실제 DB에는 아직 적용하지 않았다. 이후 실제 서비스 교체 때 백업을 먼저 하고 새 버전에서 연다. 구버전은 새 DB 스키마를 거부하므로 되돌릴 때 별도 백업/복원 판단이 필요하다.

## 보관 정책 제안 — 미승인·미적용

기본값 `enabled:false`. 제안은 원시 방문 30일, 일별 집계 365일, 처리 완료/삭제 피드백 90일이다. 실행 스케줄이나 자동 삭제 API는 없다. 실제 자료 삭제는 하지 않았다.

원시 방문에는 브라우저 식별 해시, 방문 시각, 탐험 시작 여부와 활성 시간 등이 있다. IP 원문은 방문 테이블에 저장하지 않고 사용 제한 키에는 날짜별 HMAC을 쓴다. 원시 방문을 지우기 전 KST 방문 시작일별·환경별 방문 수, 일 고유 브라우저 수, 재방문 수, 탐험 수, 활성 시간 합을 저장한다. 일별 고유 수를 더해 기간 고유 수로 표시하면 안 된다. 집계에는 방문자 식별값/동선/본문이 없다. 최근 살아 있는 세션이 포함된 날짜는 건드리지 않는다.

집계 기간도 지나면 해당 집계를 삭제하므로 관리 화면의 누적 방문은 보관 중인 기간의 합이며 영구 누적이 아니다. 방문자 식별 기록이 삭제된 뒤에는 재방문 판별이 초기화될 수 있다. 방명록 소유자 자격과 글/신고는 이 방문 보관 정책에서 삭제하지 않는다. 미처리 피드백도 자동 삭제하지 않는다. 백업의 보관/삭제는 별도이며 이 명령이 백업을 지우지 않는다. 서버 접근 로그 보관은 실제 호스팅 확정 후 따로 정해야 한다.

읽기 전용 미리보기(명시한 기존 스키마2 DB에만 실행, 자동 마이그레이션 없음):

```sh
node scripts/retention112.cjs --database /absolute/test/community.sqlite
```

적용은 정책 JSON에 `enabled:true`, `approvedBy`, `approvedAt`와 보관 일수를 명시하고 `--apply --confirm-delete`를 함께 줘야 한다. 운영자가 정책을 승인하고 별도 백업을 확인하기 전 이 명령을 실제 DB에 실행하지 않는다. CLI의 확인 문구는 관리자 인증을 대체하는 원격 기능이 아니라 로컬 운영자의 실수 방지 장치다.

## 이용자 안내 초안 — 공개 전에 확정

“방명록은 공개되며 이 브라우저의 작성 자격으로 수정·삭제합니다. 피드백은 관리자만 확인합니다. 비밀번호·연락처 등 개인정보를 적지 마세요. 접속 유지, 글 관리와 도배 방지를 위한 쿠키를 사용하며 방문은 브라우저 기준으로 집계합니다. 보관 기간과 문의 방법은 공개 전 확정해 안내합니다.”

이 초안은 확정 개인정보 처리방침이나 법적 검토를 대신하지 않는다. 미승인 보관 기간이 이미 시행 중인 것처럼 제품에 표시하지 않았다.

## 공개 전에 남은 검증

실제 모바일 Safari/Chrome, 외부 TLS/프록시/WS 재접속, 운영 호스트의 CPU·메모리·대역폭·디스크/백업 복구·경보는 아직 미확인이다. 관리자 접근 보호와 OS 업데이트, CDN/프록시 공격 방어는 호스트 선정 후 검증해야 한다. 로컬 120초 가상 사용자 시험은 장시간 운영 안정성이나 인터넷에서 300명 서비스를 보장하지 않는다.

## 운영 준비 기준 추가

사용자가 선택한 준비 기준은 DigitalOcean Basic 2GiB·공유1vCPU·50GiB SSD와 일간 백업이다. 계정 생성·결제·실서버 설치·공개 배포는 하지 않았다. Singapore는 후보이고 리전은 실제 지연 확인 전 미확정이다. 비용·계약 조건 확인과 구매는 별도 담당 문서에서 관리한다. 로컬 최대 RSS 약231MiB만으로 이 호스트의 전체 메모리/CPU 여유를 확정하지 않으며, 300명 밀집·재접속·순간 지연을 실제 인스턴스에서 다시 확인해야 한다.
