# 운영 준비 — BUILD112 기준 갱신

이 파일명은 이전 링크 호환용이다. 현재 기본 운영은 **공용 캠퍼스 하나·300명 상한·가까운 최대24명 표시**, Node24 이상 + ws8.23.0 + SQLite 스키마2다. 이전의 3채널·업체미정·스키마 변경 없음 설명을 대체한다.

사용자 선택은 DigitalOcean Basic 2GiB / 공유1vCPU / SSD50GiB / 일간 VM 백업이다. Singapore는 후보이며 리전·도메인은 미확정이다. 계정 조작·실서버 설치·결제·공개 배포는 이번 작업에서 수행하지 않았다. 실제 8766 서비스와 데이터는 보존했다.

구체적인 설치 순서, 감시, 백업·복구는 [OPERATIONS112_RUNBOOK.md](OPERATIONS112_RUNBOOK.md)를 따른다. 보안/원시 자료 보관 정책은 [SECURITY_RETENTION112.md](SECURITY_RETENTION112.md), 개인정보 원시 자료 정리와 백업 보관은 서로 다른 정책이다.

## 구성

한 HTTPS origin이 정적 장면·`/api/`·`/multiplayer`·`/ready`를 제공한다. Nginx 예시는 모든 요청을 Node에 전달하여 실제 경로 검사와 관리자 CSP를 우회하지 않는다. API/WS/ready에 캐시를 사용하지 않는다. Node는127.0.0.1:8766만 수신한다. 단독 프록시 환경에서 `CAMPUS_TRUST_PROXY=127.0.0.1`, 정확한 `CAMPUS_PUBLIC_ORIGIN`과 덮어쓴 Host/X-Forwarded-Proto/X-Forwarded-For가 필요하다. CDN을 추가하면 검증된 공급자 프록시 범위로 실제 IP 복원 설정을 별도로 검증해야 한다.

관리자 암호·DB·WAL·백업·restic 비밀번호와 저장소 자격은 checkout 밖에 둔다. DB와 `private.json`을 함께 보존해야 기존 글 소유권 서명과 관리자 자격이 유지된다. 새 버전 실행 시 스키마1→2 추가 테이블 생성이 있으므로 실제 전환 전 일관 백업을 먼저 만든다. 구버전은 스키마2를 거부한다. 되돌릴 때는 새 경로 복원 후 전환하며 운영 DB에 덮어쓰지 않는다.

## 복구·감시

프로세스 오류는 systemd가5초 뒤 재시도하되300초 안에 시작5회를 넘으면 멈춘다. 부팅 시 시작은 설치 후 `enable`해야 적용된다. 정상적인 운영자 stop은 자동 재시작 대상이 아니다. 서버 전체 장애는 동일 서버 안의 스크립트만으로 알릴 수 없으므로 외부 HTTPS 가용성 검사를 사용한다. systemd OnFailure는 로컬 journal 기록이지 이메일 발송이 아니다.

선택적으로 운영 백업 상태를 `/ready`에 연결한다. 실패·30시간 초과·20분 이상 진행 중인 백업은503이며 게임의 다른 API를 강제 차단하지 않는다. 이것은 프로세스 재시작 명령도 아니며 자동 DB 복구를 실행하지 않는다. 백업 게이트를 켠 `/ready`는 로드밸런서에서 무조건 인스턴스를 빼는 용도로 사용하지 말고 외부 운영 알림 용도로 해석한다.

로컬 검증은 별도 테스트 DB·포트로 수행했다. 실제 Linux systemd/Nginx 구문 검사, 재부팅/재시작 폭주, 외부 이메일 수신, VM백업 복원, 원격 암호화 저장소 복원은 아직 미확인이다. 실제300명 운영·DDoS 방어·무중단·무료 무제한을 보장하지 않는다.
